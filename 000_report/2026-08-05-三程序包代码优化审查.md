# dSIBP 仓库三程序包代码优化审查报告（复核修订）

- 日期：2026-08-05
- 对象：`package-FlintNDE`、`package-MadStree`、`package-dSibp`
- 当前版本：FlintNDE `0.1.0.dev0`、MadStree `v0.5`、dSIBP `020`
- 审查类型：只读代码审查与优化建议，未修改任何程序包源码
- 复核说明：保留原报告的 H/F/M/L 编号和逐项发现；dSIBP 部分改以 `versions/020_dSIBP/` 为对象，并对原建议标注“建议实施、条件实施、不建议实施”
- 验证边界：本轮未运行测试或数值计算；历史测试计数不作为本轮结论

## 结论摘要

原报告对重复位置的识别大多有事实基础，但重复行数、函数长度和理论复杂度不能直接证明优化收益。复核后的取舍如下。

| 包 | 建议实施 | 条件实施 | 不建议按原方案实施 | 当前最高优先级 |
|---|---|---|---|---|
| FlintNDE | H2、H3、H4、H7、H8、H11、M1、M2、M4、M5 | H1、H6、H9、M3、M6 | H5 的统一 schema、H10 的行数阈值、M7、L2-L5 专项化 | H2：选择性收敛公共数值层 |
| MadStree | F1、F4、F9、F20、F21、F24 | F2、F3、F5、F6、F8、F10-F15、F17、F22 | F7、F16、F18/F19 跨版本单副本、F23 共享可变框架 | F1/F4；F8 经 benchmark 后决定 |
| dSIBP 020 | H1、H3、H5 | H2、H4、M2-M4、L1-L2 | M1 的跨冻结版本去重、L3-L5 专项化 | H1：清理被覆盖的旧 DownValue |

总体判断：三个包均存在演进期复制残留，但只有 dSIBP H1 已构成明确的静默维护风险。FlintNDE 和 MadStree 的多数建议属于可维护性优化；涉及数值 gate、缓存、context schema、独立验证和冻结版本时，必须先证明合同一致或实际性能收益。

静态审查不能证明“当前结果不受影响”。准确表述应为：本轮未发现由这些重复直接导致的已知结果错误，但未运行任何测试，源码重构前后都必须取得 fresh 基线。

- 保留原报告对 FlintNDE 当前模块、MadStree v0.5 Kernel/Backend/tests/validation、dSIBP Kernel/check-smoke/independent-benchmark 的静态盘点。

## 一、FlintNDE（`package-FlintNDE`）

### 高收益

**H1. Frobenius power-log 递推内核重复 5 份**

原发现成立：`frobenius.py:200-255`、`392-443`、`540-585`、`636-695` 与 `numeric_structure.py:554-608` 具有同源的 `right_by_log`、projector inverse、resonance 修正和零尾裁剪流程。

**判断：部分合理，条件实施。** 五段代码分别承担 exact gate 生成、exact gate 消费、numeric gate 生成/消费等职责，零判定、共振目标、矩阵类型和 fail-closed 条件不同。原建议的单一 `_power_log_recurrence(..., on_gate)` 参数不足以表达这些差异。应先增加 characterization tests，再依次提取卷积、非共振 inverse、gate key 完整性和尾部裁剪；只有这些步骤稳定后，才评估带明确 exact/numeric adapter 的统一递推器。

**H2. `core.py` 与 `regular_point_de.py` 整组工具函数重复**

原发现基本成立：工作精度、范数、相对差、列向量、单位矩阵，以及 `transport.py` 与 `regular_point_de.py` 的 Taylor/Horner 工具均有重复。

**判断：合理，建议实施。** 应让 `regular_point_de.py` 和 `epsilon_jet_de.py` 选择性复用公共层，同时保留不同输入合同。`core.column_vector` 会转换整数/字符串 exact 实数，`regular_point_de` 还处理复数 InputForm；不能整组机械别名，也不能用实数 `exact_rational` 代替复数解析。公开 API 保持不变。

**H3. 输运主段循环在 `transport.py` 内重复**

`transport_path` 普通段与 `_transport_frobenius_boundary_batch` 共享最近奇点距离、Cauchy 越界检查、Taylor 系数、求值和 report 流程。

**判断：合理，建议实施。** 提取只负责普通段执行的内部函数；边界初始化、局部基、snapshot 和保存点语义仍由调用者控制。

**H4. 按 identifier 查 inventory 重复至少 6 处**

**判断：合理，建议实施。** 可给 `SingularityInventory` 增加 `find_finite(identifier)` 或只读索引，并统一缺失错误；主要收益是避免错误处理漂移，不宣称在通常很小的奇点集合上有显著性能提升。`transport.py` 中完全相同的 singular initialization report 也可单独提取。

**H5. Acb JSON 序列化家族重复 5 处**

**判断：原发现把不同合同混在一起，不建议按原方案实施。** `savepoints.py:20-28` 保存 midpoint 与独立 radius；`numeric_structure.py:104-111` 保存无 ball 的 numeric manifest midpoint；`regular_point_de.py`、example/check 又使用不同的 `re/im/re_ball/im_ball` 或 `abs` 字段。不能用 `include_ball` 布尔参数把这些 schema 合成一个函数。仅 `examples/qnm_2x2.py` 与对应 check 中字段完全相同的 serializer 可以共用，列向量 helper 也只在字段和形状检查一致时复用。

**H6. `routing.py` 两个建路函数高度重叠**

**判断：部分合理，条件实施。** `build_adaptive_path` 与 `build_adaptive_path_plan` 可以共享坐标反演、inventory、端点分类、内部奇点扫描和局部基预检；前者生成可执行路径、detour 和 transition，后者生成诊断计划，不能强行合成一个完整 walker。`build_adaptive_path_plan` 的匹配点计算可复用 `_ordinary_match_point`，前提是保持其诊断语义。

**H7. check/test 公共 helper 逐字重复**

**判断：合理，建议实施。** 两个 `check_01` 脚本中相同的 `load_json`、模块加载和 SHA-256 helper 可进入 check 专用公共模块；`test/test_kECep_16x16.py` 只复用实际相同部分。helper 不进入 package 公开 API。

**H8. JSON 落盘 pattern 重复**

**判断：合理，建议实施。** 采用同一输出目录合同的 example/check 可复用 `OutputLayout.write_json`。`SavePointWriter` 有即时逐点写入、序列号和 summary schema，继续保留独立职责，不为表面相同的 `json.dumps` 强制改写。

**H9. 参数校验/精度目标解析重复**

**判断：部分合理，条件实施。** `0 < x < 1` 与字符串阈值解析只有在异常类型、参数名、精确/近似输入和边界值语义一致时才提取。否则局部显式校验更清楚。该项不列为高收益。

**H10. 过长函数清单**

**判断：不能单凭行数成立，不建议作为独立重构指标。** `build_adaptive_path`、`reconstruct_series_solution` 等可在后续功能修改时围绕可独立测试的数据阶段拆分；“超过 150 行”不是验收条件。`regularization.py` 两处验证循环若输入和异常合同相同，可作为 M5 的局部提取处理。

### 中收益

- **M1 tests setup 重复：建议实施。** 建立 `tests/_helpers.py`，集中精度初始化、临时目录、保存点 glob 与 JSON 读取；每个测试仍显式表达自己的断言。
- **M2 exact 规范解与矩阵列工具重复：建议实施。** `boundary.py` 与 `local_solutions.py` 中完全相同的 exact solve、column/matrix-from-columns 可下沉到不造成循环依赖的 exact 模块；Acb 版保持不同入口。
- **M3 InputForm 清洗重复：条件实施。** 可提取最低层文本正规化函数，但 `exact_gaussian` 必须继续只依赖 python-flint，不能为了去重反向依赖 `core` 或 SymPy 路线。
- **M4 `savepoints.py` 与 `output_layout.py` 路径安全重复：建议实施。** 可共享“单层文件名”验证；两类 writer 的目录和 schema 职责继续分开。
- **M5 `regularization.py` 内部重复：建议实施。** distinct 校验和相同 Horner 可局部共用；异常证据不同的校验不要合并。
- **M6 examples bootstrap 样板：条件实施。** 当前 example 可统一相对 package root 与 output layout；示例仍应可单文件直接运行，不依赖测试 harness。
- **M7 平凡透传包装：不建议仅因透传删除。** `frobenius.py`、`singularities.py` 的包装可能在隔离 `GaussianMatrix` 和稳定模块边界；只有确认没有接口或依赖隔离作用后才考虑删除。

### 低收益

- **L1 `transport.py` 缩进异常：** 先由 formatter/语法检查确认；若只是视觉缩进，随邻近改动修复。
- **L2 refinement warning 合并：** 可随相关路径重构处理，不单独立项。
- **L3 `_matrix_column` 仅用一次：** 保留或内联都无实质收益。
- **L4 `asymptotics.py` 与 `matrix_norm_inf` 求和形状相似：** 只有范数定义完全相同才复用，不能只按循环形状判断。
- **L5 分支字符串常量：** 仅在需要跨模块共享或静态检查时提常量。

### 复核新增发现

**H11. 为多种 Acb serializer 建 schema 合同测试，而不是统一实现**

**判断：建议实施。** 当前 serializer 的差异多数是有意的数据合同，但缺少一处清楚列出 schema 名、必需字段、是否包含 ball/radius、是否允许 round-trip 的测试矩阵。新增合同测试可逐一锁定 `savepoints`、numeric manifest、regular-point result 和 example/check 字段；以后只共享完全相同的实现，字段漂移会立即失败。这比带布尔开关的万能 serializer 更安全。

## 二、MadStree（`package-MadStree`，v0.5 为当前工作版本）

### 高收益

**F1. 运行目录/绝对路径 helper 两模块复制**

原发现部分成立：`Artifacts.wl` 与 `Numerics/FlintNDE.wl` 的调用目录判定和绝对路径正则相同。

**判断：合理，建议实施。** 可建立 `Kernel/Core/Paths.wl`，共享运行目录、绝对路径判断和受控目录创建。两个 resolver 的 `Automatic` 语义不同：formula artifact 生成 `results/madstree_formula/run-UUID`，FlintNDE runtime 返回调用目录；具体 resolver 不合并。

**F2. sector/line 查找 O(n)，缺 context 级缓存**

**判断：事实成立，收益未证明，先 benchmark。** `msSectorByKey` 与 `msLineById` 的确线性扫描，但 sector/line 通常可能很小。先在代表 family 记录调用次数和 wall time；若值得优化，优先在一次 formula/boundary 计算的局部作用域建立 Association。只有确认 context 经常复用，且新增索引不改变 digest、导出大小和 context 身份后，才写入 context。

**F3. InputForm 字符串键 Association 模式重复**

**判断：部分合理。** 可提取只负责 `ToString[#,InputForm]` 建索引的小函数，但必须明确返回值是位置、对象还是 bit；不同用途不应被一个含糊 helper 统一。优先级低于 F1/F4。

**F4. slot-key 定位已有 helper 却各自重写**

**判断：合理，建议实施。** `Sectors.wl` 与 `Recurrence.wl` 中相同的 slot 查找应调用 `msSlotPositionByKey`，并统一 UnknownSlot 返回；不同缺失处理不机械替换。

**F5. 非 System 符号提取模式重复三处**

**判断：部分合理。** 只有三处对 held expression、去重顺序和排除 context 的要求相同，才建立公共 helper；公式 time-power、kinematic 和 boundary required symbols 仍可保留各自命名入口。

**F6. Failure 构造样板重复**

**判断：部分合理。** 可以统一 `InitializedContextRequired` 和 `UnknownSector` 的返回合同，尤其修复 Missing/Failure 与直接索引混用；不建议建立万能 Failure builder，因为不同函数需要不同证据字段。

**F7. connection 沿路径求导一行重复**

**判断：不建议单独抽象。** 两处一行 `Map[D[...],{2}]` 不足以支持新 helper；只有未来出现统一的路径 pullback 合同时再处理。

**F8. Diagonalizer U/UInverse 反复重建**

**判断：潜在收益高，但必须 benchmark。** U 是 sector 的共同对角化矩阵，UInverse 是其逆矩阵；Kronecker product 与 `Simplify` 可能昂贵。先测量 U/UInverse、`msM0Inverse`、energy letters 和 dlog 生成的耗时与表达式大小。优先使用一次 formula 构建内的局部缓存；直接写入 sector Association 前评估 context 体积、identity certificate 和导出影响。

**F9. targetRules 过滤 energy 规则重复**

**判断：合理，建议实施。** 建立命名明确的 helper，并用测试固定它只过滤 vertex energy 左端，不误删其它动力学规则。

### 中收益

- **F10 `MSFlintNDETransport` 双分支：条件实施。** 可先构造共同 inputData，再追加分支差异；不改变 JSON adapter schema。
- **F11 单顶点 Frobenius 系数重复：条件实施。** 在同一 `Boundary.wl` 内合并完全相同的 coefficient 计算和 order 读取。
- **F12 `msValidateTreeInput` 表驱动：不以表驱动为目标。** 可提取重复谓词，但每项错误证据和顺序应继续清楚可读。
- **F13 `MSBoundaryData` 长 Association：条件实施。** 只按已有子数据合同拆 helper，不为减少 key 数量改变结果 schema。
- **F14 `msSectorCanonicalStateData` 嵌套深：条件实施。** 优先分离状态分类和最终组装，并保留 quotient/canonical 顺序。
- **F15 `msHTohMatrix`/`msHToHMatrix` 镜像：条件实施。** 若参数化后公式仍直观且测试覆盖两个方向，可合并为局部 basis matrix helper。
- **F16 All overload 模式：不建议。** 为三个一行 overload 建高阶 `msSectorWideLookup` 会增加间接层而没有真实复用收益。
- **F17 JSON 读写：部分合理。** 可封装 `Import`/`Export` 的结构化失败；不统一加 `Quiet`，以免隐藏有用诊断。

### 低收益与冻结资产

- **F18 跨版本 Kernel MD5 相同：仅作事实记录。** v0.3/v0.4 已冻结，不修改、不删除、不共享当前文件。
- **F19 Backend 三版本相同：不采用单副本或 junction。** 冻结版本必须自包含、可独立复现和跨平台。v0.5 Vendor 的同步可由发布流程和哈希检查管理。`__pycache__` 已被 Git 忽略，项目规则允许本地保留，只禁止进入 staged/commit。
- **F20 test/ 与 Examples 加载样板：建议实施于 v0.5。** test 可使用 `_harness.wls`；正式 Examples 仍保持可直接运行，并显式加载 v0.5。
- **F21 test 汇总约定：建议实施。** 统一 `checks`、失败键、通过计数和退出码，不统一 case 专属输入。
- **F22 derivative dlog 与 core 断言重叠：条件实施。** 可共享 fixture 或低层 expected，但两个测试若证明不同合同则继续保留。

### 独立验证框架

**F23. 17 个 `run_validation.wls` 模板重复，6 份 `DirectBoundaryOracle.wl` MD5 相同**

**判断：重复事实成立，但原修复方案不合理。** 当前 `AGENTS.md` 明确规定每个独立验证目录的验证程序、专用 oracle、结果和报告归该任务目录所有。若改为共享可变 `_lib/validation_framework.wls` 或把 oracle 移到公共目录，冻结报告将依赖外部当前文件，破坏来源隔离和可复现性。

允许的改进是维护一个“生成下一轮验证的模板/脚手架”；创建新验证任务时把完整框架和 oracle 快照复制进任务目录，并记录 digest。已有 v0.3/v0.4/v0.5 验证目录不追溯改写。

### 复核新增发现

**F24. 为当前 v0.5 Vendor/FlintNDE 建受控文件哈希同步检查**

**判断：建议实施。** MadStree v0.5 当前需要自带 FlintNDE，但不应依赖 junction 或冻结版本公共副本。可在 v0.5 发布检查中列出实际 vendored 的受控源码文件，与 `package-FlintNDE/versions/FlintNDE-v0.1.0.dev0/` 逐文件比较哈希，同时明确允许 README、配置或 adapter 专属差异。该检查只报告漂移，不在运行时复制文件，也不追溯修改 v0.3/v0.4。

## 三、dSIBP（`package-dSibp`，020 为当前工作版本）

### 高收益

**H1. 跨文件同名函数被后加载模块覆盖，`LoopCore013.wl` 存在死定义和分歧源**

该发现已在 020 重新确认。加载顺序为 `LoopCore013.wl`（`Kernel/dSIBP.wl:120`）之后加载 `KinematicCoordinates.wl:134`、`SectorModel018.wl:135`、`TimeOnlyRepresentation020.wl:136` 和 `RelationsParity018.wl:137`。以下相同左端定义仍有语义分叉：

| 函数 | 被覆盖定义 | 020 运行时定义 | 已确认差异 |
|---|---|---|---|
| `makeBaseIntegral` | `LoopCore013.wl:935` | `SectorModel018.wl:125` | time-only 时 ISP 槽是否为空 |
| `enumerateDiscreteStates` | `LoopCore013.wl:1329` | `SectorModel018.wl:91` | raw binary 与 quotient representative metadata |
| `discreteVarsForLine` | `LoopCore013.wl:1312` | `SectorModel018.wl:56` | masslessFull 单槽与双端点状态 |
| `ds` 三参 | `LoopCore013.wl:6924` | `RelationsParity018.wl:662` | sector prefactor、sector-aware canonical 与 020 表示转换 |
| `rep2Integrand` 两参 | `LoopCore013.wl:7029` | `RelationsParity018.wl:775` | bare integrand 与 sector prefactor 恢复 |
| `normalizeNumericRulesForTopology` | `LoopCore013.wl:2031` | `KinematicCoordinates.wl:777` | square-root 坐标规则处理 |

**判断：合理，建议最高优先级实施。** 但不能按同名扫描一次性删除，也不以“预计删除 400-500 行”为验收。实施前记录加载后的完整 `DownValues`，逐个确认后加载定义覆盖所需签名，并检查旧函数体中的 helper 是否仍被其它路径调用。每次只清理一个逻辑组，修改前后运行直接相关 smoke，最终重跑 14 个 `check-smoke`，专项覆盖 full-loop/time-only、lower-sector prefactor、massless quotient、square-root 数值规则、`ds` 和 integrand。

**H2. 错误处理样板跨文件重复**

`Message[...]`、`dsErrorPrint[...]`、结构化失败返回确实大量重复。

**判断：部分合理，条件实施。** 可以建立只负责构造统一失败 Association 的 `dsFail[tag,reason,extra]`，前提是先审计哪些接口返回 `$Failed`、哪些返回 Association、哪些透传已有失败数据。不建议建立能替外层执行 `Return` 的通用 `dsGate`：helper 内 `Return` 不会自然退出调用者，若引入 Hold 或 `Throw`/`Catch`，风险大于减少的样板。

**H3. `check-smoke` 14 个脚本头/尾样板重复**

**判断：合理，建议实施。** 可建立 check-smoke 专用 harness，统一当前版本入口解析、`results_test`、checks 汇总、失败键和退出码。每个 smoke 保留自己的 case 输入和断言；harness 不得被独立验证读取，也不成为正式 package 依赖。

**H4. 双语消息文本双源维护**

**判断：方向合理，分模块迁移。** 新增或修改公开错误时，先定义 `Symbol::tag` 中英文模板，由调用点只传参数；`dsErrorPrint` 保留为醒目输出层，不再维护另一份不同措辞的业务文本。不建议一次性让 `dsErrorPrint` 自动读取任意 Message，因为 slot、格式化参数和内部诊断并不总是一一对应。

### 中收益

- **M1 版本目录逐字复制：不作为当前优化。** 018/019 是冻结快照，020 是当前主线；跨版本重复是版本纪律的预期结果。发布流程可记录“预期未变文件”的哈希或 diff，但不修改冻结目录。
