- `MSBoundaryData`（自动 Frobenius 边界）→ `MSFlintNDETransport`（序列化 v2 pole/residue → `flintnde_transport.py` → FlintNDE 0.2.0 `PartialFractionSystem`）→ `MSEvaluateTree`（端到端）；examples 直接复用这条链。

## 发现

### F1（中）`flintnde_cache/` 运行缓存未纳入 `.gitignore`

1. **预期契约**：AGENTS.md 与各包 README 约定"程序包源码目录不接收运行产物"；UPDATE_NOTES（v0.8）自述"`flintnde_cache/` 目录由 MadStree 自动创建，属调用目录产物"。
2. **实际实现**：`.gitignore` 无 `flintnde_cache` 规则；`git check-ignore package-MadStree/versions/MadStree-v0.8/test/flintnde_cache/2f749abe63ab492e/backend_output.json` 返回非匹配（未被忽略）。`git ls-files --others` 列出 11 个 `backend_output.json` 缓存文件。
3. **触发条件**：对 `MadStree-v0.8/` 执行 `git add`（研究计划已标"已完成"，即将提交）。
4. **直接后果**：运行缓存（后端输出快照）进入版本目录与 commit，仓库体积膨胀，缓存随机器/精度变化污染版本身份。
5. **下游传播**：提交内容审查困难；缓存与源码 digest 不一致时误导后续复核。
6. **证据与复核**：上表 check-ignore 输出；`git ls-files --others --exclude-standard | Select-String flintnde_cache` 列出 11 个文件（本文档开头）。
7. **修复边界**：在 `.gitignore` 增加 `**/flintnde_cache/`（或 `package-MadStree/**/flintnde_cache/`）；不必改 MadStree 缓存写盘逻辑。
8. **验收方法**：`git check-ignore` 对缓存路径返回匹配；`git add -A` 后 `git ls-files` 不含 `backend_output.json`。

### F2（中）example 01 缺省运行失败，"examples fresh 全过"声明引用的是历史证据

1. **预期契约**：研究计划 2026-08-10 任务验收标准写"MadStree v0.8 开发测试与 examples fresh 全过"；README 第 176 行写"五个 examples 中 01--03 已从 v0.5 迁入 v0.7（v0.5 源码 fresh 运行均退出 0）；04、05 端到端退出 0"。
2. **实际实现**：v0.8 `Examples/01_massless_full_edge.wl` 的 `MSEvaluateTree`/`MSFlintNDETransport` 调用均未传 `PythonExecutable`，沿用缺省 `"python"`。当前环境（wolframscript 内部 `!python`/`Run`）解析到无 python-flint 的解释器，导致 `userAnchorValue` 为 Failure、`userFiniteBoundary` 的 `values` 非 List、`MSFlintNDETransport` 返回 `BoundaryVectorDimension`，batch 全部失败且脚本仍 `exit=0`（无失败门禁）。
3. **触发条件**：在 PATH 中 python 无 `flint` 模块的机器上按 README 说明直接 `wolframscript -file Examples/01_*.wl`。
4. **直接后果**：示例演示失败，`Lookup::invrl`/`MapThread::mptd` 刷屏，用户误以为 batch/自定义边界功能损坏；退出码 0 掩盖失败。
5. **下游传播**：example 是用户学习入口，失败掩盖会影响对 v0.8 新功能（batch、自定义边界、dense output）的信任。
6. **证据与复核**：缺省运行输出含 3 次 `BoundaryVectorDimension` 与 `MapThread::mptd`，`exit=0`；探针确认 `MSEvaluateTree` 返回 `Failure[FlintNDEProcessFailed, ModuleNotFoundError: No module named 'flint']`。显式 `PythonExecutable -> "D:/anaconda/python.exe"`（或 `SetOptions` 覆盖）后 example 01 全链路（含 batch 与导出）退出 0；probe2 显示 `userTargetValue status = computed`。`D:/anaconda` 探测 `flint OK 0.9.0`，无需安装。
7. **修复边界**：不改数值逻辑；建议 examples 顶部统一探测解释器（读取 `MADSTREE_PYTHON` 环境变量、候选 `D:/anaconda/python.exe` 等），并在 example 尾部加失败门禁（batch 任一 Failure 时 `Exit[1]`）。
8. **验收方法**：无环境变量、无 conda 前置 PATH 的缺省机器上 example 01 应 fail 明确（非刷屏 + exit 0）；设置 `MADSTREE_PYTHON` 或探测到可用解释器后应退出 0 且无 `invrl` 输出。
