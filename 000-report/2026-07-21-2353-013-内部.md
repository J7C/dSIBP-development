## 修正前差异与归因

修正前 hash `6160C6...15B9F` 的首轮 full actual 在当时的统计 schema 下为 `159 passed / 5 failed`。5 个失败全部是局部 `letterOrderPass`；letter 集合、dlog connection、按 letter 对齐后的矩阵、binary state 顺序和 master 顺序均一致。差异如下：

| case/vertex | 修正前 actual 顺序 | 冻结 expected 顺序 |
|---|---|---|
| two/v1 | `{-E1-k12,-E1+k12,k12}` | `{k12,-E1-k12,-E1+k12}` |
| two/v2 | `{-E2-k12,-E2+k12,k12}` | `{k12,-E2-k12,-E2+k12}` |
| three/v1 | `{-E1-k12,-E1+k12,k12}` | `{k12,-E1-k12,-E1+k12}` |
| three/v2 | `{-E2-k12-k23,-E2+k12-k23,-E2-k12+k23,-E2+k12+k23,k23,k12}` | `{k12,k23,-E2-k12-k23,-E2-k12+k23,-E2+k12-k23,-E2+k12+k23}` |
| three/v3 | `{E3-k23,E3+k23,k23}` | `{k23,E3-k23,E3+k23}` |

这也会使两个 case 的全局 letter 顺序与冻结顺序不同。归因为确定性序列化顺序错误，不是物理公式或矩阵内容错误。冻结 convention 是按 `vertexOrder` 遍历，每个顶点追加 `{massiveLegs 能量 letters, binary cut letters}`，最后稳定 `DeleteDuplicates`，保留共享内部能量的首次出现。

修正后 hash `ACD23F...FE9A` 上，5 个局部 order、2 个全局 order、对应 letter set、全部对齐矩阵和 master/state 顺序均通过；冻结 expected 未作反向修改。

## 表示对齐与限制

- 冻结关系用完整物理指数；package 的 tree `J` 首槽保存整数 `a`，`a0` 保留为 `nu0` metadata。比较器使用文档化的可逆映射。
- loop h endpoint 的显式能量通过 `b -> b-1` 表示，投影到 tree 后才恢复为显式 `k`。
- contact 投影比较完整 `(-k)^(-2 nu-1)`，不是只比较整数 `k^-1`；符号比较把 `(-k)^p` 规范为 `(-1)^p k^p`。
- 冻结 helper 对 `p=1` 会机械调用单参数 `KroneckerProduct`。actual checker 使用数学等价的单因子特例；未修改冻结 expected。该限制只影响 helper 的执行形式，不改变冻结矩阵、关系或顺序。
- manual 的相关接口页在第二阶段已渲染检查；源码与 PDF 对上述 tree 指标、loop `b` shift、contact prefactor 和 `G+-` guard 的说明一致。
