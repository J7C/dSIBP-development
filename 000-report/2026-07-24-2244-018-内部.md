## 1. 结论摘要

当前 018 的门禁不是“全部多余”，但层次混在了一起。应保留的是三类检查：用户首次提交 topology/ISP/动量/坐标/范围等约定时的防呆，外部 Kira artifact 回流时的身份与闭合检查，以及防止递推不终止或未推导公式被误用的数学边界。其余内部数据若由同一条密封主线产生，应依赖一次生成的状态摘要和内容 digest，不应在每个 consumer 再全量扫描。

本审计确认最需要精简的默认热路径是：

1. `DSLinear` 对全部关系重做 sector/class/generator/forbidden-`n`/canonical coverage；应由 `DSGenerateIBP` 一次生成摘要，`DSLinear` 只消费摘要。完整系统与局部系统应使用 `completeSystemQ` 区分，不应把局部线性化一律拒绝。
2. 密封模板在 `DSGenerateIBP` 中重算全集合 SHA-256，但 raw expression 可绕过同一要求；当前门禁既昂贵又不一致。应改为密封状态和明确的 complete/subset 语义。
3. 已按 parity provenance 预筛的密封主线仍在生成后扫描每条关系中的全部 `J`；完整后验 certificate 应移到 raw/unsealed 输入或显式审计模式。
4. formal Kira plan 已构造 active-basis 导数闭包，export 又从原始 `linearData` 完整重构；plan certificate 未用于验证 export 实际消费的对象。应传递 prepared data，或删除伪 certificate。
5. `DSInit` 已成功构造数学 context 后，会因可选初始化文件写入失败而把整个 context 改成 failed；I/O 状态应与数学初始化状态解耦。
6. tree `LinearSolve` 后的全方程 `Together` residual、公开表示的全对象扫描及 dlog residual 都属于开发证书；除 raw/外部输入外，不应默认重复运行。
7. Kira import 的确需要硬边界，但同源判据目前比较 package version 和若干 context 字段，却没有比较实际导出方程、映射和 targets 的内容 digest。版本字符串不应替代 artifact 身份。

已记录的 bubble+tree 全量流程中，`DSGenerateIBP` 为 126.24 秒，`DSLinear` 为 346.51 秒，共有 397,592 条关系和 65,252 个积分（`研究计划与研究进度.md:33`）。这证明线性阶段值得优先剖析；但本轮没有分项计时，不能把 346.51 秒全部归因于 coverage 门禁。

初始审计时 018 还存在 `E018-15` normalized-`J` prefactor/contact/`ds` 正确性阻塞；该项随后已按结构化 `N_s` 路线修复并完成局部复验，但 reference 全闭环和正式候选晋升仍未完成。精简门禁不能被解释为 018 已可晋升，也不能用删除检查掩盖尚未闭合的数学问题。正式交付仍是 016。

2026-07-25 专项复核确认：018 的 `F11=-F00` 只是已经抽出每次端点导数动量因子的无量纲 quotient，不能单独解读为原始导数恒等式。cycle line 由每次 `b->b-1` 承载模长，fixed line 由每次显式乘 `sE1` 承载；两次作用后分别精确重现同端点 `-q^2` 与交叉端点 `+q^2`。但正式 016 fresh-kernel 仍输出 massless cycle 二槽 `{b,n}`、fixed 单槽 `{n}`，没有三槽或字符串 sentinel；因此这些功能在 018 开发主线已实现，在当前正式程序包 016 尚未交付。完整证据见第 11 节。

## 5. 按严重度排列的发现

### F1（高）：Kira import 的同源硬门禁可能拒绝兼容结果，也可能接受同版本 stale reduction

- 预期契约：导入结果必须与实际导出的方程、积分映射、targets、数值规则完全同源。
- 实际实现：`dsKiraContextMatchQ` 比较 `packageVersion`、context `inputHash`、zero-point、symmetry、tadpole 和 projection convention（`KiraImport.wl:104-111`）；manifest 没有覆盖序列化方程内容、映射和 targets 的统一 content digest。
- 触发：同一 `"018"` token 内关系实现变化，或兼容修订改变版本字符串但未改变导出内容。
- 直接后果：前者可能接收 stale reduction，后者会拒绝内容完全一致的 reduction。
- 下游：`DSDE` 信任 `DSKiraImport` 的 `validationReport`，错误身份会传播到 DE/scaling。
- 建议：export 对 canonical serialized equations、`repJ2Kira/repkira2J`、targets、coefficient rules、active-basis payload 生成统一 SHA-256；import 以 digest 为主。版本只保留 provenance 信息。
- 验收：同内容不同 patch version 可导入；同版本改变任意一条方程、map、target 或规则必须拒绝；旧 manifest 缺 digest 时明确返回 legacy/unverified，不静默通过。

### F2（中）：`DSLinear` 在大系统上执行不必要的全量重复 coverage

- 预期契约：同源 sealed producer 已证明的属性由状态摘要向下游传递；consumer 只做廉价身份检查。
- 实际实现：`makeCanonicalSeedCoverageReport` 多轮 `Select`/分类全部 equations，并重新核对 sector、IBP class、generator、forbidden `n`、canonical 和计数（`LoopCore013.wl:4717-4785`）；`makeLinearSystemData` 无条件调用并硬拒绝（`LoopCore013.wl:5813-5822`），之后还再次 symmetry（`5831`）。
- 触发：每次 `DSLinear`，包括 397,592 条关系的正式热路径。
- 直接后果：确定存在 O(N) 多轮扫描；现有总计时显示 linear 阶段比 generate 阶段更慢，但本轮没有 coverage 分项计时。
- 下游：局部、探索性、分块 linearization 也被“完整系统”门禁阻断。
- 建议：`DSGenerateIBP` 在生成时累积 `{sector,class,generator,count,forbiddenNCount,canonicalStatus}` 摘要；`DSLinear` 核对摘要 digest。允许 `completeSystemQ->False` 的 linearData，只有 formal reduction plan 才要求 complete。
- 验收：sealed 完整系统不再调用 `classifyCanonicalSeedBatch`；相同输入的 integral/equation 顺序与字节保持一致；合法 subset 能生成 `linearData` 但不能被误标为 complete/formal。

### F3（中）：template integrity 门禁对 structured/raw 输入不一致

- 实际实现：structured records 要求 hash/count/ordinal 完全覆盖，否则 `templateIntegrityFailed`（`GenerateIBP.wl:476-495,809-814`）；raw expression 返回 unsealed，随后不触发同一硬失败。
- 后果：用户从密封模板中选择合法 subset 会被拒绝，而去掉 metadata 反而可继续；门禁鼓励丢失 provenance。
- 建议：区分 `sealedComplete`、`sealedSubset`、`unsealedRaw`。hash 用于身份，不用于禁止所有 subset。formal plan 才要求 complete，普通 generate/linear 允许 subset 并显式降 capability。
- 验收：同一 subset 的 structured/raw 路线得到相同方程；structured 路线保留 provenance；两者都不能伪称 complete。

### F4（中）：plan/export 重复构造 active-basis closure，certificate 没有约束 consumer

### 11.1 预期契约与记号分层

原始指数 kernel 的临时双端点导数标签满足

```text

{20} = {02} = -q^2 {00}
{11} = +q^2 {00}
```

该契约仍明确写在 `000_note/dS_IBP_package_plan.md:102-117` 和 `000_note/dS_IBP_package_design_note.md:266-284`。其中 `{10}/{01}` 是有序端点方向关系；`{11}/{00}` 是含动量模平方的微分恒等式，不应称为图对称性。

并由端点导数算符另行携带 `+/- I sigma q`。该分层见 `000_note/dS_IBP_package_tech_note.tex:405-434`。所以 `F11=-F00` 只有在以下动量因子链同时成立时才正确；脱离 `b` shift/显式系数单独引用会得到错误的物理解释。
