## 4. 已发现的不符合与责任判定

### N1. `DSSeeds` 缺省值与手册合同不一致

- 手册附录 A 写“离散态=all”。
- 实际 `Options[DSSeeds]` 继承 `DiscreteMode -> Automatic`。
- `Automatic` 由 topology 的 `seedOptions` 解析；缺省 `seedPreset -> "quickCheck"` 时实际落到 `"sample"`，因此不与 `"all"` 行为等价。

判定：不是手推错误，也不是 IBP 公式缺陷；这是公开 package API 与用户手册合同不一致。当前 preset 设计、examples 显式传 `"all"` 以及规模门禁共同表明 `Automatic` 是有意的工程默认，因此优先建议把手册改为“`Automatic`，由 preset 决定；`quickCheck -> sample`”。若产品意图确实是公开入口缺省全离散，则应修改 package 默认并重新评估规模门禁，不能只改文字。

### N2. 手册版本状态文字过期且前后矛盾

首页 abstract、第 1 节和加载示例仍称 012 为稳定核心、014 为计划，并指向 `package_012.wl`；第 9--11 节和附录 A 已描述实际存在的 014 标准 package、Kira importer、DE 与 scaling API。

判定：不是手推错误，也不是 package 物理缺陷；需要更新手册的版本状态、加载入口和“当前未实现”段落。

### N3. benchmark 与 package 的 ISP 输入 schema 不一致

- 任务书使用 `{"id","expression"}`。
- 014 package validator/examples 使用 `{"name","expr","range"}` 或三元组 `{name,expr,range}`。
- 本轮 check 在 package-facing 层使用显式一一 adapter；手推公式仍只依赖任务书中的表达式和槽位顺序。

判定：不是手推错误，现有 adapter 下也没有 package 数学差异；这是 benchmark/user API convention mismatch。建议任务书直接采用 package schema，或在任务书中正式规定该 adapter，避免独立检验者把格式拒绝误报为 ISP 闭合失败。

## 5. 结论

本轮补齐的 ISP、H/h、tree/common-theta 和 general-`ds` 手推均与 014 package 对齐；物理关系比较中未发现非零差值。不能继续表述为“package 完全不存在缺陷”：至少存在 N1 的公开 API/手册合同不符合；N2、N3 是文档或输入 convention 不符合。修复优先级应为：先同步手册当前版本和 `DSSeeds` 缺省语义，再统一 ISP schema；除非决定改变公开缺省行为，否则本报告不建议修改 IBP 物理实现。
