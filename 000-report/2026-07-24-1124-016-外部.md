## 3. 审计发现

### 3.1 发现 #1: UTF-8 编码加载 [环境注意事项]

**逻辑链路**:
1. `package_016.wl` 文件编码为 UTF-8（hex 验证：`E6 98 AF` = "是"）
2. Windows 系统默认 `$CharacterEncoding` 非 UTF-8
3. WolframScript 默认用系统编码读取 → 中文字符串被错误解析 → line 18 触发 `Syntax::sntx`
4. Package 加载不完整 → `$dSIBPVersion` 未赋值

**修复**:
```mathematica
Get["package_016.wl", CharacterEncoding -> "UTF-8"];
(* → Version: 016 ✓ *)
```

**严重程度**: minor（有明确 workaround）
**建议**: package 文件头添加 BOM 或在文档中注明编码要求。

### 3.2 发现 #2: timeOnly 族 StringRiffle 消息格式化 bug [cosmetic]

**逻辑链路**:
1. `ibpMode -> "timeOnly"` 且 `loopExternalMomenta -> {}` 时，无外部运动学不变量
2. DSInit 内部尝试生成 "可用 DSRedefineParameters 重定义参数" 的提示信息
3. 参数列表为空/缺失时，`StringRiffle` 收到非法输入 `"KeyAbsent" -> custom1^2 -> ...`
4. 触发 `StringRiffle::list` 和 `StringJoin::string` 警告

**关键代码片段** (package 内部消息生成):
```
StringRiffle::list: List expected at position 1 in
  StringRiffle["KeyAbsent" -> custom1^2 -> "KeyAbsent" -> custom2^2, , ].
```

**影响**: 仅产生警告消息，**不影响功能**。DSInit 仍返回 `status -> "initialized"`，
DSSeeds/DSLinear 在正确输入下正常工作。
**严重程度**: cosmetic
**触发条件**: timeOnly 族 + 无 loopExternalMomenta（如 atomic_massless_line、atomic_massive_line）

#### 7.4.1 发现 #3: shrinkSectorSeedGeneration 待实现功能 [重要]

**现象**:
当 `generatorSeedRanges` 显式包含 shrink sector (e1/e2) 的生成元时：
```
DSSeeds: status="generated", 59392 equations
         pendingFeatures: {shrinkSectorSeedGeneration}
DSLinear: status="notReady", reason="pendingFeatures"
          → "linearData 未通过 canonical/linearity 门禁"
```

**完整逻辑链**:
1. Bubble+tree 拓扑有 3 个 sector: top (全线在), e1 (line 1 shrunk), e2 (line 2 shrunk)
2. `generatorSeedRanges` 中显式写入 `"sectorKey" -> "e1"` 或 `"e2"` 的生成元后，
   DSSeeds 尝试为这些 shrink sector 生成 seed 方程
3. 但 package 016 对此拓扑的 shrink sector seed 生成尚未实现
   （`pendingFeatures` 返回 `{shrinkSectorSeedGeneration}`）
4. DSSeeds 仍然返回 `status="generated"`（仅生成了 top sector 的方程），
   但携带 `pendingFeatures` 标记
5. DSLinear 检测到 `pendingFeatures` 非空，触发门禁拒绝，返回 `status="notReady"`
6. 后续 DSKiraExport 因缺少 linearData 而失败

**解决方案**:
`generatorSeedRanges` 中**仅包含 top sector** 的生成元，不写 e1/e2。
Shrink sector 的方程由 package 内部自动处理（通过 shrink 编码从 top sector 派生）。
去掉 e1/e2 后：
```
DSSeeds: pendingFeatures: {} (空!)
DSLinear: status="generated", linearQ=True, 12343 integrals, 59490 equations
DSKiraExport: status="ready"
```

**对比参考**: pure_massive_bubble (example 04) 的 `referenceGeneratorSeedRanges` 包含 e1/e2
且工作正常，说明该功能对 2-顶点 bubble 已实现，但对 3-顶点 bubble+tree 尚未实现。

**严重程度**: 中等（功能限制，非 bug；有明确 workaround）
**影响范围**: 所有 3+ 顶点且含 shrink sector 的拓扑

#### 7.4.2 发现 #4: Parity 规则必须覆盖全部线 [审计方错误]

**错误**: 初始版本仅检查 massive h line 的 parity (`OddQ[n11+n12+b1]`)，
遗漏了 massless exp line 2 (`OddQ[n2+b2]`) 和 bridge line 3 (`OddQ[n3]`)。

**后果**: 大量本应归零的积分留在系统中，导致 master 数量虚高 (483)。

**修正后的完整 parity**:
```mathematica
(* line 1 (massive h): n11+n12+b1 为奇 → 0 *)
(* line 2 (massless exp cycle): n2+b2 为奇 → 0 *)
(* line 3 (massless exp bridge): n3 为奇 → 0 *)
btParityZeroQ[J[_, {{b1_, n11_, n12_}, {b2_, n2_}, {n3_}}, {}]] :=
  TrueQ[OddQ[n11 + n12 + b1] || OddQ[n2 + b2] || OddQ[n3]];
```

**参考**: example 04 的 `exampleParityZeroQ` 对每条线独立检查（`OddQ[n1+n2+b1] || OddQ[n3+n4+b2]`）。

#### 7.4.4 主积分数量异常分析 [1652 明显偏多]

**预期**: 对 bubble+tree（1 massive h + 2 massless exp）加上完整 parity，
真实主积分应在 ~20-100 量级（参考: pure_massive_bubble 有 19 masters）。

**实际**: 1652 masters。

**异常原因链**:

1. **shrink sector 方程缺失**（根本原因）:
   - 12343 个积分中，绝大多数属于 shrink sector (e1/e2)
   - 但 59490 个方程几乎全部来自 top sector 的 5 个生成元
   - Shrink sector 积分没有对应的 IBP 方程来约化它们
   - 结果: 大量 shrink sector 积分被 Kira 判定为 "master"
   - 这是 `shrinkSectorSeedGeneration` pending feature 的直接后果

2. **Power::infy 奇点**:
   - DSKiraImport 时出现 `1/0` 和 `ComplexInfinity + ComplexInfinity`
   - 表明约化系数在给定数值点有极点
   - 可能原因: zeroPointRules 中的参数值使某些 IBP 系数分母为零
   - 数值点: `{dim->37/11, nu1->5/11, alpha1->3/7, ..., beta1->-1/3, ...}`
   - 待查: 是否某个 `a0[vi]` 或 `b0[i]` 的值恰好使 shrink 编码中的 Gamma 函数参数命中极点

3. **contextConventionMatch 失败**:
   - Part 2 重建的 context 与 Part 1 export 的 manifest 不匹配
   - 可能原因: `dsibp-export-manifest.wl` 中记录的 context hash
     与 Part 2 重建的 context 不一致（即使参数相同，内部状态可能不同）
   - 也可能与 Power::infy 相关: 如果 import 过程中遇到无穷大，
     系数变量识别会失败

**结论**: 1652 masters 不是真实物理主积分数，而是方程系统不完备的表观结果。
要获得正确的主积分数，需要 package 实现 shrink sector seed 生成，
或者审计方手动构造 shrink sector 的 IBP 方程。

**当前状态**: §17.4 bubble+tree 闭环因 `shrinkSectorSeedGeneration` 功能限制而**阻塞**。
这不是 package bug，而是待实现功能。已在报告中记录为功能限制。
