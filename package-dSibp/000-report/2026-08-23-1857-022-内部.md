### 3.2 已确认缺陷

**预期契约。** Active UserMI manifest 保存 `Tuserweight[i] -> userMI[i]`，技术说明也规定 import 的
公开 `masterTokens` 使用 `userMI[i]`，随后 `DSDE` 应把所有导数目标约回同序 19 项。

**实际实现。** `package_022.0.wl:11557-11563` 在 active route 中已选择 `activeExpressions` 和
`activeUserMITokens`，但构造 `reductionRules` 时只应用 `repKira2J`：

```wl
reductionRules = reductionRulesRaw /. Normal[Association[repKira2J]];
```

它没有应用同一 manifest `activeBasis -> userMI -> backendToUserMIRules` 中已经存在的 21 条规则。

**触发与后果。** 使用 `DSUserMI` active basis 导出并 fresh 取回 Kira reduction 时，右端 master
token 仍是 `Tuserweight[1..19]`。所有 import provenance/coverage 门禁都通过，但公开 `DSDE`
返回 `status -> "notClosed"`，19 个 backend token 全部残留，矩阵不能作为正式结果使用；因此
后续 `DSScaleCheck` 也没有合法输入。

**定位性诊断。** 在 `reductionData` 副本中只应用运行前已冻结的 21 条
`backendToUserMIRules`，再调用同一个公开 `DSDE` 后：residual backend token 为 0，`P0`、`ip0`、
`ks` 三个 `19x19` 矩阵分别 `361/361` 与 reference exact 相等，fixed parameter residual 为空。
该结果证明 Kira reduction、论文矩阵和根因定位正确，但它不是 public package route，不能把
bubble case 改写为通过。

**修复边界。** 应在 `DSKiraImport` 的 active-basis consumer 层，把 validated manifest 的
`backendToUserMIRules` 应用于 reduction RHS；不得放宽 artifact identity、master order、target
coverage、系数域或 residual 闭合门禁，也不得在 `DSDE` 中加入猜测 token 名称的 fallback。

**验收。** 修复后原样 fresh `DSKiraImport -> DSDE` 必须：状态 `generated`；0 个
`Tuserweight` residual；同序 19 masters；`P0/ip0/ks` 各 `361/361`；篡改/缺失 active map 的
反例仍 fail closed。诊断 adapter 应删除，不成为兼容入口。
