## 1. 结论摘要

当前 016 **不能认证为正确性通过**。本轮在最小代表 case 和当前实现路径上确认三个 package 缺陷：

1. atomic massless `timeOnly` 同分支 contact 项丢失 fixed-line 的物理模长幂 prefactor，导致五条 `++` 关系的 exact 数值行空间不相同。
2. `ds` 在合法 lower/contact sector 上先按 root topology 的 `aList` 长度校验，因 `expected 2 / actual 1` 返回 `$Failed`，阻断 lower-sector DE。
3. massless `timeOnly` 目前只保留三槽 line state，没有完成按顶点/时间打包及两条 massless 额外关系的同步变换；在额外关系形成的 quotient 上，旧 `repIterative`/dlog 公式不能直接沿用。

当前 package 已能把含未缩并 `masslessFull` 的 atomic `++` seed 保留为三槽表示，这只证明有向 line state 没有在入口丢失；它是合法的原始/中间表示，不等于已经完成 `timeOnly` 表示。此前把这一步写成 representation 通过项不准确，本版报告已纠正。

pure massless bubble 的关系层在删除六条 package 额外输出的精确零行后通过：双方均为 26 条非零关系、rank `26/26`、RREF 完全相同。问题发生在 lower-sector `ds`，不是该 family 的 IBP 行空间。

## 4. 已确认缺陷

### F1（高）：atomic massless contact 丢失 fixed-line 物理模长幂

#### 预期契约

任务书 `independent-benchmark/independent-benchmark.md:193-202` 规定 `timeOnly` active line 使用 fixed-coefficient schema；fixed line 的 zero-point、normalization 和 shrink prefactor 不进入 `J` 指标，必须留在关系系数中。该任务书 `:269-298` 进一步把 atomic 同分支的被积函数固定为含 `q1^(-beta1)` 的三槽对象。

当前 `++` 的三槽原始信息保留正确；最小探针得到

```text
PACKS={masslessFull}
NEEDS_LINE=True
REP=J[timePowers,linePacks,isp]
```

#### 实际实现与触发条件

正式 package `package_016.wl:3642-3714` 的 shrink 代码只在 fixed line 上乘 `magnitude^(-bShift)`。massless theta boundary 在 `:3722-3754` 固定 `bShift -> 0`，因此被移除 fixed line 已有的 `b0=beta1` 物理幂没有进入 contact coefficient。

最小触发是 `atomic_massless_line`、分支 `++`、top-sector time generator。代表差异为：

```mathematica

actual contact coefficient:   -2
```

在本轮 exact 点上分别为 `-2 (307/83)^5` 与 `-2`，严格不相等。

#### 直接后果与下游传播

错误不是单纯表示差异：即使只取有向 line state 已完整保留的 `++` 三槽关系，规范行空间仍不相同。任何从该 relation system 构造的 `linearData`、Kira 输入或 contact-sector 约化都会使用缺少 fixed physical power 的关系。

#### 修复边界

修复应落在 fixed-line shrink coefficient 的构造层：移除 fixed line 的 `J` pack 时必须把该 sector 的完整物理幂转换为显式模长系数。不得给 fixed line 伪造 `b/bS` 整数槽，也不得改变 cycle-line 的已有 `bShift` 语义。

#### 修复后验收

只重跑 atomic `++` 五条关系，在同一有理点要求：

- nonzero rows `5/5`；
- rank `5/5`；
- RREF 完全相同；
- contact coefficient 精确包含 `sE1^-beta1`；
- 转换前的三槽对象仍完整保留 fixed-line `n` state，后续 `timeOnly` 转换不得以修 prefactor 为由丢失该信息。

### F3（高）：massless `timeOnly` 尚未在额外关系 quotient 上闭合

#### 预期契约

massless 传播子相对 massive 情形多两条独立关系。利用这两条关系后，time-only 状态可以进一步简化为当前讨论的两槽表示。正确流程不能只删除状态或直接套用为加入这两条关系之前推导的 `repIterative`/dlog 公式；package 至少必须做到：

1. 从完整三槽 line-based 对象构造按顶点、按时间打包的 `timeOnly` 表示；
2. 把两条 massless 额外关系作为一等 relation 一并变换到该表示；
3. 在加入额外关系后的 quotient basis 上重新构造迭代约化和 dlog DE。

这不否定三槽表示的用途。三槽表示可以作为不丢信息的原始表示或中间表示，但不能被当作 `timeOnly` 转换已经完成的证据。

#### 当前实现

正式 package `package_016.wl:8785-8818` 的 `dsTimeOnlyNeedsLinePackStateQ` 在发现未缩并 `masslessFull` 时改走 canonical 三槽路线。direct pure-time 模块在 `:9504-9522` 明确只把 massive h state 放进 vertex pack，并把任何未缩并 `masslessFull` 列入 unsupported lines；`makePureTimeSeedBatch` 随后可返回 `reason -> "masslessFullNeedsTreeState"`。

因此当前行为是：

```text
masslessFull three-slot information retained: yes
converted to vertex/time-packed timeOnly basis: no
two extra massless relations transformed with the basis: no
quotient recurrence/dlog rebuilt: no
```

#### 为什么旧公式不能直接使用

令 `F(x)` 是加入 massless 额外关系前的 time-only basis，旧公式为

```mathematica
D[F[x],x] == Omega[x].F[x]
```

两条额外关系写成

```mathematica
S[x].F[x] == 0
```

选取 quotient 后的独立 basis `m(x)`，并用满列秩矩阵 `C(x)` 表示

```mathematica
F[x] == C[x].m[x]
```

再取任意满足 `L[x].C[x]==IdentityMatrix[...]` 的左逆。约化后的连接必须是

```mathematica
OmegaReduced[x] == L[x].(Omega[x].C[x] - D[C[x],x])
```

而不是简单删除 `Omega` 的若干行列。若 `C` 含能量、模长或 normalization，`-D[C,x]` 项不可省略。最终只用约化后 dlog 与独立 naive 路线的 exact 数值一致性验收，不另设额外的微分闭合门禁。

迭代约化同理。若旧一步关系是

```mathematica
Rminus[a].F[a-1] + R0[a].F[a] + Rplus[a].F[a+1] == source[a]
```

则必须对每个 shift 同时代入 `F[a+s]==C[a+s].m[a+s]`，并与对应的额外关系 `S[a+s].F[a+s]==0` 一起组成增广线性系统，再 row-reduce/求解新的单步规则。不能先对旧 `Rminus/Rplus` 求逆得到 `Aminus/Aplus`，再事后删除冗余状态；这两步一般不交换。

#### 两个备选实现顺序

**方案 A：先转为 time-only，再加入额外关系。**

```text
three-slot J + sector metadata
  -> relation-aware timeOnly packing
  -> transformed massless relations
  -> quotient basis
  -> new repIterative / dlogDE
```

优点是 `timeOnly` 语义直接，按顶点/时间打包后的关系可直接服务 tree 模块。风险是转换不能先丢弃 line `n`；必须先产生可审计的 basis map，并证明两条额外关系完整到达目标表示。

**方案 B：三槽中先加入额外关系，再把积分和关系整体转为 time-only。**

```text
three-slot J
  -> augmented system {IBP relations, massless extra relations}
  -> three-slot quotient
  -> transform quotient basis and every relation to timeOnly
  -> new repIterative / dlogDE
```

优点是 line orientation、sector 和额外关系来源在原始表示中最清楚，也便于复核当前三槽实现。风险是不能只转换积分对象而把 symmetry/extra relations 留在三槽层；`timeOnly` 模式必须把 relation module 一起转换，否则下游仍会回到未约化的旧 basis。

最终采用方案 A、方案 B，或把二者分别作为 producer 与独立 check，**当前待用户决定**。无论选择哪一方案，最终的 quotient basis、关系行空间、迭代结果和 dlog 连接必须一致。

#### 修复边界与验收

package 应为转换保存：source/target basis、sector key、每个积分的映射、两条额外关系的映射、rank、pivot/non-pivot states，以及是否含运动学相关系数。`DSLinear`、serializer、`repIterative` 和 `DSTreeDLogDE` 必须消费同一 quotient 身份，不能各自重新猜 basis。

只需一个 atomic massless `++` exact case 验收：

- 输入三槽对象保留全部 line state，转换后得到约定的两槽 time-only 表示；
- 两条额外关系在转换前后 rank 相同，且转换后的增广关系行空间 exact 相同；
- `masslessFullNeedsTreeState` 不再作为合法 family 的终止状态；
- 新单步迭代 relation 的增广系统 residual 精确为零；
- 若 basis map 依赖 `x`，故意删掉 `-D[C,x]` 的 mutation 必须被检出；
- naive 路线与 quotient 后 dlog 路线在同一个非奇异有理点得到相同矩阵。

这里不要求大规模符号化简或 Kira reduction。

## 8. 修复顺序

1. 修 fixed-line contact coefficient，确保已有物理幂进入显式 prefactor。
2. 冻结两条 massless 额外关系及其三槽/time-only 槽位定义；由用户决定方案 A、方案 B，或双路线 producer/check 分工。

4. 修 sector-aware public expression resolution，使 `ds` 在校验前解析 compact sector。
5. 只重跑 atomic massless `++` 与 pure massless bubble 两个最小 case。
6. 上述项通过后，再用一个统一 normalization 的 mixed massive exact case和一个最小 contact-tree exact case收尾。
7. 只有 correctness blockers 清零后，才生成最小 serializer/Kira 输入检查；package 本身仍不得运行 reduction。
